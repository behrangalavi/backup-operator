# 0002. Chart ships CRDs as templates with `resource-policy: keep`, and ships no CRs — recipients are seeded by the operator

**Status:** Accepted. Written under the labelled-Secret model; Secret/annotation names map to CRD fields as listed in [the mapping](README.md#pre-crd-names).

Helm's `crds/` directory installs CRDs but never upgrades them, which would freeze the schema at the first install; templating them (`templates/crds.yaml` ← `files/crds/*.yaml` via `.Files.Glob` + `fromYaml`) lets `helm upgrade` evolve the schema, and the `keep` annotation stops `helm uninstall` from deleting every BackupSource in the cluster along with the CRD. The catch: Helm applies templated CRDs and CRs in one batch without waiting for the CRD to be established, so a `BackupRecipient` manifest in the chart fails the very first install with "no matches for kind". Hence `agePublicKeys` travels as the `BOOTSTRAP_AGE_RECIPIENTS` env var and the operator creates the objects at startup (idempotent, `AlreadyExists` ignored, never deletes). A `pre-install` hook Job was the alternative; rejected because it leaves permanent hook complexity in the chart for a one-time ordering problem the operator can solve in 30 lines.
