# 0073. Bounded `path` label on the request-duration histogram (`normalizeMetricPath`)

**Status:** Accepted.

`latencyMiddleware` records `backup_operator_http_request_duration_seconds{method,path,status}`. The old normalization collapsed the six parametric CRUD prefixes but recorded every other path verbatim — and because the `/` SPA handler is a catch-all that serves any URL and unknown `/api/*` paths return 404 (still observed), an unauthenticated scanner walking `/wp-admin`, `/.env`, `/a/b/<random>` minted a fresh histogram series per distinct path, each carrying the full bucket set and living for the pod's lifetime: an unbounded-memory / scrape-bloat DoS on the operator's own registry. The UI has no built-in auth ([§3.1](../getting-started.md#31-securing-the-ui-with-an-authentication-proxy)), so this has to be closed at the metric layer, not assumed away by a proxy. `normalizeMetricPath` now maps to a closed set: parametric routes collapse to their prefix, a hard-coded allow-list of the mux's fixed routes passes through, and **everything else becomes the single label `"other"`**. Adding a new fixed route means adding it to `metricKnownPaths` (or `metricPathPrefixes` if parametric) — otherwise it just shows up under `"other"`, which is a safe default rather than a leak. Regression-tested that a flood of distinct unknown paths collapses to one series.
