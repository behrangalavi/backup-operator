# 0111. SSRF egress guard on UI-initiated storage dials (`checkDestinationEgress`)

**Status:** Accepted.

The UI has no built-in auth ([§3.1](../getting-started.md#31-securing-the-ui-with-an-authentication-proxy)) and can create destinations, so a caller could point a destination's `host` (sftp/ftps) or `endpoint` (s3) at `169.254.169.254` (cloud metadata / IMDS) or an internal service and use the differentiated `test-connection` / `destination-stats` / `destination-health` / `consistency-check` errors as a reachability oracle from the operator's network position. Fix: a guard at `storageForPool` — the single choke point every UI storage path routes through (diagnostics, `/download`, dashboard probes, `listTargets`) — resolves the user-controllable host and refuses to build the client (so the dial never happens) when it points at a blocked range: loopback, link-local (covers 169.254.0.0/16 and fe80::/10 IMDS), the AWS IPv6 metadata address (`fd00:ec2::254`, a ULA the link-local checks miss), unspecified, and multicast. RFC1918 / generic ULA are deliberately NOT blocked — in-cluster MinIO, a LAN NAS, and internal SFTP hosts are the operator's core use case; constrain those further with the opt-in NetworkPolicy. Placed at the construction choke point rather than per-handler because construction is where the (unauthenticated) request first turns into an outbound client, and putting it there covers every current and future UI dial path in one spot. Trade-offs: (a) azure/gcs hosts are derived subdomains of fixed cloud domains, so they have no attacker-chosen host to check; (b) DNS rebinding (TOCTOU) can still re-resolve a name to a blocked IP between the check and the storage layer's own dial — the guard raises the bar against the trivial literal-IP / metadata-hostname attack but is defence-in-depth, not a NetworkPolicy substitute; (c) on DNS resolution failure the guard does not reject, letting the real dial surface its normal sanitized error. The worker's fan-out dials are intentionally out of scope (they run from Secrets and upload only age-encrypted ciphertext; their egress is the NetworkPolicy's job). Regression-tested for metadata/loopback rejection and RFC1918/AWS allow.
