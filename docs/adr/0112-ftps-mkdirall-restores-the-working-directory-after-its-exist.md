# 0112. FTPS `mkdirAll` restores the working directory after its existence probe

**Status:** Accepted.

`mkdirAll` recurses each path segment; when `MakeDir` returns 550 (ambiguously "already exists" or "permission denied") it probes with `ChangeDir` to tell them apart. But `ChangeDir` **mutates the session CWD** and the old code never restored it, while every `MakeDir`/`Stor` here uses a full path resolved against the login directory. So the first "segment already exists" probe left the CWD inside the tree, and the next `MakeDir` targeted `<cwd>/<full-path>` — a doubled prefix (`~/t` → `MakeDir("t/2026")` → `~/t/t/2026`) whose parent doesn't exist → 550 → the whole create failed. This broke the Phase-2 meta upload (a fresh connection that re-runs `mkdirAll` on an existing tree) on **every** FTPS destination whenever the `path-prefix` was relative or empty; an absolute prefix masked it because absolute paths don't depend on CWD, and it also poisoned the shared `WithSession` connection for later List/Delete. Fix: capture `CurrentDir()` before the probe and `ChangeDir` back immediately after, so every segment's `MakeDir` runs from the login dir. If the server doesn't support `PWD` we can't restore, so we skip the probe and treat 550 as "probably exists" (letting `Stor` surface any real problem) rather than corrupt the session. `mkdirAll` now takes a 3-method `ftpDirClient` interface so the CWD logic is unit-tested with a fake server (existing-dir → CWD-restored + no doubled path; no-PWD → probe skipped; genuine failure → surfaced) without a live FTP server.
