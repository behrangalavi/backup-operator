# 0122. Degraded empty-dump detection is surfaced as a warning, NOT enforced via an absolute byte floor

**Status:** Accepted.

When `CollectStats` is unavailable (analyzer disabled, or stats query failed — e.g. redis AUTH on `INFO`), `BuildVerification` returns `skipped` and the empty-dump heuristic can't fire: SQL compares stream row counts against `preStats`, mongo/redis compare encrypted size against `preStats` total, and all need the baseline. A header-only redis/mongo dump (server exited 0 but emitted nothing) would then pass since only `encryptedSize == 0` hard-fails. The obvious fix — an absolute byte floor independent of `preStats` — was rejected: `encryptedSize` is the size *after* age encryption, whose header scales with recipient count (~60 + N×130 bytes), so any fixed floor either misses real failures or false-fails legitimate tiny dumps. Per the project's own "false-positives are worse than rare misses" principle (the heuristic-threshold ADR), a noisy hard-fail is the wrong trade. Instead, when `EmptyDumpCheck && preStats == nil` the run emits `BackupEmptyCheckDegraded` (warning) + logs, so the gap is visible and an operator can act, without risking a false hard-fail on a healthy backup. Engine-agnostic (keyed only on `preStats == nil`), so it also respects the [§8.2](../conventions.md#82-factory-pattern-is-mandatory) "don't branch on type strings outside the factory" rule.
