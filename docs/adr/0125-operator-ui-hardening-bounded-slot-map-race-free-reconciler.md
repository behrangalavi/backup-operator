# 0125. Operator/UI hardening: bounded slot map, race-free reconciler client, single SSE reconnect

**Status:** Accepted.

Four latent issues with no observed failure yet, fixed pre-emptively. (1) `MetricsRefresher.perDestSlots` (the per-destination concurrency-semaphore map) grew unbounded under destination churn — every distinct name ever seen leaked one channel + entry for the operator's lifetime. Now pruned each tick via `retainDestSlots`, mirroring `Pool.Retain`; safe to delete mid-tick because the refresh only fans out to current destinations, so an absent name has no in-flight goroutine and deleting the map entry never closes a live channel. (2) `RecipientReconciler.rebuildMergedWith` swapped the shared `r.Client` field (`r.Client = c; defer restore`) — safe only because `Bootstrap` runs before the manager starts, but a latent data race if it ever overlapped a reconcile. `rebuildMerged` now takes the client as a parameter; the field swap and the wrapper are gone. (3) `connectSSE` could stack reconnect timers / leak `EventSource`s on a flapping server (its own auto-reconnect races the manual one) — now guarded by a single `_sseReconnectTimer` and detaches the old source's `onerror` before closing. (4) `badge.running` was missing from the i18n dictionaries (rendered via a German-literal `||` fallback); added to en/de/fr and the suspended case reuses the existing `badge.paused` key.
