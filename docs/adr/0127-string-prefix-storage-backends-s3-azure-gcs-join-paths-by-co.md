# 0127. String-prefix storage backends (S3/Azure/GCS) join paths by concatenation, not `path.Join`

**Status:** Accepted.

`full()` used to be `strings.TrimLeft(path.Join(pathPrefix, p), "/")`. `path.Join` runs `path.Clean`, which strips the trailing slash a List prefix carries for target isolation: `full("db/")` collapsed to `prefix/db`, and because S3/Azure/GCS List is a pure string-prefix match, that also matched the sibling target `prefix/db-archive/...`. The consequences were severe and silent: retention for `db` (which round-trips the bled paths correctly through `stripPrefix`) deleted `db-archive`'s dumps — even with `db-archive` set to `retention-days=0` (keep forever) — and the analyzer baseline / `last_success` metrics for one target were populated from another's meta. The restore CLI's `--purge` inherited the same bleed, so a DSGVO-erasure for one customer could destroy another's artifacts. Fix: `full()` concatenates `pathPrefix + "/" + p`, preserving the caller's trailing slash exactly (Upload/Get/Delete pass paths without a trailing slash, so they are unaffected), and `stripPrefix` trims the full `pathPrefix + "/"` boundary instead of the bare prefix (so a sibling `prod-eu/...` under prefix `prod` is never mangled into `-eu/...`). SFTP/FTPS were never affected — they walk a directory tree, not a string prefix. Object stores treat a literal `..` as an inert key component, so dropping `path.Clean` here does not introduce traversal; traversal via the target *name* is closed separately at the parser (below).
