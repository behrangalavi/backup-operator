# 0128. Structural identifiers (source target name, destination name, path-prefix) are validated at parse time

**Status:** Accepted. Written under the labelled-Secret model; Secret/annotation names map to CRD fields as listed in [the mapping](README.md#pre-crd-names).

`TargetName` and destination `Name` come from the `backup.mogenius.io/name` annotation and flow into `path.Join`-built object keys, metric labels, and CronJob names; `path-prefix` is the object-key root. None were validated, so a source annotated `name: ../../other-tenant` wrote (and let retention delete) outside the destination's prefix — defeating the [§6.4](../crds.md#64-backupdestinationspec) isolation contract. `ParseSource`/`ParseDestination` now reject names not matching `^[A-Za-z0-9][A-Za-z0-9._-]*$` (no `/`, no leading `.`, ≤253 chars) and any `path-prefix` containing a `..` segment. This is a hard rejection (the Secret is skipped), not the forgiving-fallback treatment feature-flag annotations get — a name is structural, like the required `host`/`username` keys, so a bad one must fail loudly rather than be silently rewritten. Behaviour change: existing sources with a `/` or space in the name annotation (already broken in the hash router and questionable in paths) now stop producing CronJobs until renamed.
