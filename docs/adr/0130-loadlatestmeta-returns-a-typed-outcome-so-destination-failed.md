# 0130. `loadLatestMeta` returns a typed outcome so `destination_failed` can catch runtime storage failures

**Status:** Accepted.

The function used to collapse "no meta uploaded yet" and "storage unreachable / unreadable" into a single `found=false`. The refresher's per-destination goroutine `return`ed on `!found` without touching the gauge, and because `Pool.Get` only *constructs* a client (SFTP/S3 constructors never dial — the connect/auth happens later in `List`/`Get`/`WithSession`), a rotated password or an offline host left `destination_failed` at its last value (0 = healthy). `BackupDestinationFailing` — documented in [§14](../failure-modes.md#14-failure-modes) as the "one destination down" alert — could therefore never fire for that exact failure mode; the only path that ever set the gauge to 1 was a config-parse error in the factory. Fix: `loadLatestMeta` now returns `metaOK` / `metaEmpty` / `metaError`. The refresher sets `destination_failed=1` on `metaError` (I/O failure or unparseable payload), `0` on `metaEmpty` (reachable, nothing uploaded — the legitimate first-run case) and `metaOK`. The scrubber treats anything other than `metaOK` as "nothing to scrub". Trade-off: a corrupt-but-present meta now counts as a destination failure rather than being silently ignored — intentional, since a destination serving unparseable data is not healthy.
