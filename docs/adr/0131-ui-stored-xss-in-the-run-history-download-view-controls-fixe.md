# 0131. UI stored-XSS in the run-history download/view controls, fixed by correct-context escaping

**Status:** Accepted. Written under the labelled-Secret model; Secret/annotation names map to CRD fields as listed in [the mapping](README.md#pre-crd-names).

Two spots built `onclick="viewMeta(...)"` / `onclick="copyToClipboard(...)"` with the wrong escaper for a JS-string-inside-HTML-attribute context: `renderDownloadLinks` used `escHTML` (which escapes `<>&` but NOT `'`/`"`, per its own contract) on the free-form destination `name` and the run timestamp, and the meta-viewer inlined raw `JSON.stringify(data)` (full of unescaped `"` and `<`) into the Copy button's `onclick`. Since target and destination names come from `backup.mogenius.io/name` annotations and meta content includes DB-controlled table names, an attacker who controls only DB content or a Secret annotation could land markup that executes with the operator's UI privileges (Secret CRUD, trigger, exfiltration via a rogue destination). Fix: `renderDownloadLinks` uses `escJS` for every onclick argument and `encodeURIComponent` for every URL path segment; the meta-viewer Copy button is bound via a JS closure (`data-action="copy-meta"` + `.onclick = ...`) instead of interpolating JSON into an attribute. The broader pattern (delegated listeners + `data-*` over string-built `onclick`) is the durable fix and is noted as a follow-up; the remaining `onclick` sites use constrained values (K8s Secret names, fixed enums) and are not injectable.
