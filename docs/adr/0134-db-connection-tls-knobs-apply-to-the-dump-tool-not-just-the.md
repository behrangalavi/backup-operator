# 0134. DB-connection TLS knobs apply to the dump tool, not just the stats connection

**Status:** Accepted. Written under the labelled-Secret model; Secret/annotation names map to CRD fields as listed in [the mapping](README.md#pre-crd-names).

`extra-sslmode` (postgres) / `extra-tls` (mysql) were honoured only by the in-process driver used for `CollectStats`; the actual bulk-data path (`pg_dump`, `mysqldump`/`mariadb-dump`) was launched with only the password, so `pg_dump` ran on libpq's default `prefer` and could silently downgrade to plaintext against a MITM'd or misconfigured server even when the source asked for `verify-full`. Fix: postgres exposes a shared `sslMode()` used by both `connString()` and the pg_dump env (`PGSSLMODE`, plus optional `PGSSLROOTCERT`/`PGSSLCERT`/`PGSSLKEY` from `extra-ssl*`); mysql maps `extra-tls` to the client-appropriate flag via a pure, unit-tested `tlsDumpArgs` — Oracle's `mysqldump` gets `--ssl-mode=…`, MariaDB's `mariadb-dump` gets `--ssl`/`--skip-ssl` (the same binary-divergence handling as `--column-statistics`, keyed on a cached `--version` banner probe). Empty/`preferred` adds nothing, so existing deployments are unchanged. Certificate *identity* verification (`VERIFY_CA`/`VERIFY_IDENTITY`, MariaDB `--ssl-verify-server-cert`) is only emitted when a CA path is provided (`extra-ssl-ca`, or postgres `extra-sslrootcert`) — that needs a file mounted into the worker pod; without one, an enabled TLS value still enforces an encrypted channel (`--ssl-mode=REQUIRED` / `--ssl`), which is what closes the plaintext-downgrade hole. Regression-tested (`TestTLSDumpArgs`, `TestBuildDumpArgs_EnforcesTLS`, `TestSSLMode_SharedByStatsAndDump`).
