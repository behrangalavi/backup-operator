# 0135. Storage backends are measured against one conformance suite; `ErrNotFound` and `Close` joined the interface

**Status:** Accepted.

Five hand-written fakes and five backends had drifted on the details that matter for retention and purge: S3 `Delete` of a missing key succeeded, GCS/Azure/SFTP/FTPS returned provider errors, and there was no way to tell "object gone" from "transport broken" on `Get`. `storage/storagetest` now holds an in-memory, prefix-aware fake plus `Run(t, newFn)` covering round-trips, the `db/` vs `db-archive/` prefix-bleed class (regression tests for azure and gcs mirror the s3 one), `Get`-missing → `ErrNotFound`, idempotent `Delete`, logical-path listing, ctx cancellation and session semantics. Every backend maps its provider's not-found to `storage.ErrNotFound` (FTPS maps only the clear "no such file" 550, never a permission 550) and treats delete-of-missing as success; retention does the same, so a re-run after a partial purge no longer flags healthy backends as failed. `Close()` was added because the GCS client holds gRPC/HTTP connections that the pool used to drop to GC on credential rotation; the pool retires replaced/evicted clients with a 2-minute `time.AfterFunc` grace instead of refcounting — `Get` hands out bare values, every bounded caller timeout is well under 2 min, and refcounting every call site for a rotation that happens a few times a year was judged not worth the surface. `DirectoryRemover` replaced the anonymous duck-typed interface in retention so a renamed method is a compile error, and compile-time `var _ storage.X = (*impl)(nil)` assertions pin which backend implements which optional capability.
